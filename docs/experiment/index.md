# Эксперимент

Практический эксперимент проверяет устойчивость публикации статического сайта
при штатном развёртывании, ошибке healthcheck и прерывании загрузки.

## Исследовательский вопрос

Позволяет ли схема с неизменяемыми каталогами релизов и атомарным переключением
ссылки сохранить доступность предыдущей версии при сбое публикации?

## Гипотеза

Пока новый релиз загружается в staging-каталог, публичная ссылка продолжает
указывать на предыдущий релиз. Она переключается только после полной загрузки и
проверки обязательных файлов.

## Метрики

Среднее время доставки для площадки вычисляется по формуле

\[
\bar{t} = \frac{1}{n}\sum_{i=1}^{n}t_i,
\]

где \(t_i\) — время от начала шага deploy до успешного healthcheck, а \(n\) —
число повторов. Вместе со средним фиксируются медиана, минимум и максимум.

Дополнительно измеряются:

- результат HTTP-проверки;
- наличие контрольной строки релиза;
- доступность предыдущей версии при остановке загрузки;
- длительность ручного и автоматического отката;
- объём собранного сайта и число внешних запросов.

## План воспроизведения

1. Выполнить не менее трёх production-развёртываний на каждой площадке.
2. Опубликовать отдельную preview-ветку.
3. Остановить загрузку до атомарного переключения.
4. Вызвать контролируемую ошибку healthcheck.
5. Выполнить откат и проверить опубликованный URL.
6. Повторить загрузку страницы с заблокированными внешними запросами.
