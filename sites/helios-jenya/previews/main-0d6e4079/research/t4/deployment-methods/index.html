    Сравнение способов развёртывания¶

    Матрица угроз¶

    Способ Учётные данные Минимальные права Последствия компрометации Отзыв доступа
    Push в gh-pages временный GITHUB_TOKEN; реже PAT или deploy key contents: write для репозитория злоумышленник может изменить содержимое репозитория и ветку публикации в пределах прав токена завершить job, уменьшить permissions; отдельно отозвать PAT или ключ
    Pages artifact GITHUB_TOKEN с pages: write и OIDC-токен с id-token: write создать Pages deployment; исходный код достаточно читать подмена публикуемого артефакта и сайта, но запись в Git не нужна отключить workflow/environment или запретить deployment
    SSH + rsync/scp отдельный закрытый ключ и проверенный ключ хоста вход выделенным Unix-пользователем и запись только в каталог публикации изменение и удаление доступных файлов; при обычной shell-учётной записи — выполнение разрешённых команд удалить открытый ключ из authorized_keys
    FTP пароль FTP-учётной записи запись в каталог сайта перехват пароля и содержимого, подмена или частичная публикация сменить пароль или отключить учётную запись
    SFTP пароль либо SSH-ключ и проверенный ключ хоста доступ к SFTP-подсистеме и каталогу сайта подмена или удаление доступных файлов; shell можно не выдавать сменить пароль или удалить открытый ключ
    S3 API IAM-токен, временный ключ STS либо статическая пара ключей сервисного аккаунта запись объектов в один bucket; удаление требуется только для синхронизации с очисткой подмена объектов; при наличии delete — удаление сайта и его старых версий отозвать ключ, роль или bucket policy

    GITHUB_TOKEN создаётся отдельно для job, ограничен текущим репозиторием и завершается вместе с job. Права задаются через permissions; право contents: write шире простой публикации Pages. Официальная схема Pages требует для deploy-job как минимум pages: write и id-token: write, поэтому она позволяет не выдавать workflow право записи в исходный репозиторий.

    Источники: права GITHUB_TOKEN, жизненный цикл GITHUB_TOKEN, официальный workflow GitHub Pages, публикация Pages из ветки.

    Стандартный FTP передаёт пароль и данные без шифрования, тогда как SFTP выполняет операции через зашифрованный SSH-транспорт. Источники: RFC 2577 и руководство OpenSSH sftp.

    Yandex Object Storage поддерживает IAM-токены, временные и статические ключи; статический ключ действует от имени связанного сервисного аккаунта. Права можно ограничить отдельным bucket и действиями над объектами. Источники: аутентификация Object Storage и управление доступом.

    Эксплуатационные свойства¶

    Способ Атомарность Preview Откат Состояние в проекте
    Push в gh-pages переключение Git ref атомарно, публикация платформой асинхронна отдельные ветки/сайты требуют дополнительной схемы возврат ветки к предыдущему commit только анализ
    Pages artifact deployment создаётся из неизменяемого артефакта через отдельные environments или внешнюю площадку повторный deployment предыдущего артефакта/workflow реализовано и опубликовано
    SSH + rsync загрузка в новый каталог и атомарное переключение ссылки реализовано подкаталогами и branch slug переключение на сохранённый релиз production и preview опубликованы на Helios
    FTP/SFTP последовательная загрузка сама по себе неатомарна возможна подкаталогами требует сохранённой копии и операции rename только анализ
    S3 API отдельные PUT атомарны, весь набор объектов — нет отдельный prefix или bucket versioning или повторная синхронизация старой версии только анализ

    Критерии итогового выбора¶

    • минимально необходимые права;
    • возможность быстро отозвать доступ;
    • проверка подлинности целевого сервера;
    • отсутствие секрета с правами личной учётной записи;
    • атомарность публикации;
    • поддержка preview и rollback;
    • качество журналов и диагностики.

    Для Helios практическим кандидатом является SSH/rsync с отдельным deploy-ключом, поскольку этот способ поддерживает поэтапную загрузку, проверку файлов и атомарное переключение релизов.

    Для GitHub выбран официальный Pages artifact workflow. Он уже подтверждён рабочей публикацией и требует меньших прав на репозиторий, чем push сгенерированного сайта в gh-pages.
