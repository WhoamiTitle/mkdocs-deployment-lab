# P5: версии опубликованного сайта

Срез `v1.0` содержит исходные T4 и P4. Срез `v1.1` добавляет описание
фактических изменений: конфигурацию нескольких целей через `DEPLOY_TARGETS`,
матрицу доставки, версии `mike`, preview на Pages и управление `latest`.
Измерения исходного эксперимента не изменены; новые длительности и результаты
удалённых испытаний здесь не придумываются.

## Адреса на каждой площадке

| Относительный адрес | Содержимое |
|---|---|
| `/` | перенаправление на `latest/` |
| `/latest/` | перенаправление на выбранную стабильную версию |
| `/v1.0/` | сохранённая сборка из тега `v1.0` |
| `/v1.1/` | сохранённая сборка из тега `v1.1` |
| `/versions.json` | список версий и алиасов для переключателя |
| `/previews/<branch-slug>/` | последняя сборка указанной ветки, включая `main` |

Адреса относительны корню проекта, например
`https://whoamititle.github.io/mkdocs-deployment-lab/`.
Все страницы, ресурсы и поисковый индекс версии находятся внутри её каталога.
К историческим исходникам применяются текущие адаптеры переключателя и
русского поиска; текст и числовые результаты берутся из соответствующего тега.
Preview собирается обычным MkDocs, без переключателя стабильных версий.
Slug содержит хеш исходного имени: `feature/a` и `feature-a` не конфликтуют.

## Публикация и выбор latest

```bash
git tag v1.1
git push origin v1.1
```

Тег указывает на commit, поэтому может быть создан в любой ветке. Слияние
в `main` не требуется. Workflow должен присутствовать в отмеченном commit;
для старого тега используйте ручной Publish с полем `version` на новой ветке.
Первый новый запуск собирает все доступные стабильные теги, включая `v1.0`.
При следующем запуске готовые версии сохраняются без пересборки.

Допустимы `v1.0` и `v1.0.1`. Предварительные версии с суффиксами не публикуются.
Максимальная версия определяется числами: `v1.10` старше `v1.9`.
Не перемещайте опубликованные теги: workflow проверяет SHA и отвергает замену.

Select latest version с параметром `version=v1.0` меняет алиас на всех целях.
Эта операция не создаёт версию и не пересобирает страницы. Обычный push меняет
только preview; следующая публикация стабильного тега снова выбирает максимум.

## Хранение и откат

`site-builds` содержит `sites/<target-id>/production/`,
`sites/<target-id>/previews/` и `history/`. Ветки исходников не переключаются.
`delivered/github-pages/` отдельно фиксирует доставку, прошедшую HTTP-проверку:
подготовленный, но не доставленный artifact не становится основой отката.
Запись выполняется отдельным Git index. Подготовка и ручные операции используют
общую очередь, чтобы параллельные запуски не перезаписали чужие preview.
GitHub может заменить ожидающий запуск новым в той же concurrency group.

Roll back GitHub Pages меняет местами стабильный снимок и предыдущий,
сохраняя текущие preview. Если HTTP-проверка новой доставки Pages не проходит,
автоматический откат публикует предыдущий полный artifact и восстанавливает
соответствующее состояние Pages в служебной ветке. Job остаётся неуспешной.
Если предыдущего снимка нет, откат недоступен.
Проверка Pages ждёт появления точных маркеров релиза на публичном URL до
12 минут: кратковременный ответ старой версии после успешной загрузки
не считается основанием для немедленного отката. Повторные запросы получают
уникальный параметр, чтобы не полагаться на закешированный ответ.

На Helios стабильный релиз содержит все версии и алиас; `current` и `previous`
выбирают весь такой набор. Общие preview лежат отдельно и переживают откат.
Roll back Helios выбирает одну цель. Её серверный rollback не меняет желаемое
состояние других целей в `site-builds`; следующая стабильная публикация снова
доставит актуальный набор. Доставка площадок независима, общей транзакции нет.

Исходники и ресурсы старых версий дублируются в каждом каталоге: размер сайта
растёт с числом версий и preview. Автоматическое удаление стабильных версий
не настроено. Clean site previews удаляет выбранную ветку; при выборе одной
Helios-цели preview Pages также удаляется.

Проверка пяти словоформ описана на странице [локального поиска](search.md).
