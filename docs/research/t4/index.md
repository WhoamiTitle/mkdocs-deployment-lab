# T4. Безопасность способов развёртывания

Цель T4 — сравнить способы доставки статического сайта с точки зрения
необходимых учётных данных, объёма прав и последствий компрометации.

## Объект исследования

По условию задания анализируются пять категорий:

1. push в ветку `gh-pages`;
2. официальный механизм GitHub Pages artifact;
3. SSH с `rsync` или `scp`;
4. FTP/SFTP;
5. S3 API объектного хранилища.

FTP и SFTP входят в один пункт задания, но в матрице рассматриваются отдельно:
обычный FTP не шифрует учётные данные и трафик, а SFTP работает поверх SSH.
Объединять их в одну оценку безопасности некорректно.

## Граница теории и эксперимента

Все перечисленные способы входят в качественный анализ рисков. Реальное время
измеряется только там, где выполнено настоящее развёртывание:

- GitHub Pages через `upload-pages-artifact` и `deploy-pages` — рабочая площадка;
- Helios через SSH/rsync — целевая площадка после получения доступа;
- локальная атомарная публикация — контрольная базовая линия, но не замена
  измерению Helios.

Для `gh-pages`, FTP/SFTP и S3 нельзя указывать вымышленные длительности. Пока
эти стенды не созданы, по ним приводятся только свойства протокола и модель
угроз. Методика измерений описана в разделе [«Эксперимент»](../../experiment/index.md).
